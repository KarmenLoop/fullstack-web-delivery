# Field-trial scope and provenance

The first local trial used0.2.0. A complete 0.3.0 rerun then reused ten answered requirements and an existing backend in an isolated redesign, with zero repeated questions and a complete plan before source copying. Its sequence was representative page -> public inquiry -> employee reading -> administrator processing -> site/production/restart regression. The resulting instruction revision was0.4.0.

Observed repairs included invalid target-viewport assumptions, form/sign-in focus loss, a failed first focus patch, pending statistics, exit-time focus sampling, omitted service steps, hidden mobile actions, required guidance, and small phone controls. A live probe initially sent an extra login field; the corrected probe followed the actual schema. First failures remained in local evidence.

The 0.3.0 local record passed11 formal HTTP/maintenance tests,8 live API checks,18 public viewport checks,12 production routes, and data/session persistence across development-to-production and production-to-production restarts. A single inquiry matched receipt, storage, staff view, completed status/version 3, and two audit events. Keyboard and reduced-motion scenarios were operated separately.

An independent screenshot and sampled-source reviewer found five material issues and later resolved those five. Its ship result does not certify full runtime behavior, the whole visual surface, or human design approval. Other platforms, real devices, complete accessibility/performance audits, account apps, transactions, and public deployment remained untested.

Version 0.4.1 publishes English instructions, tutorials, license terms, and an English-localized example. Fresh publication checks are tracked separately in the repository's evidence. Historical counts above are not silently reassigned to the localized source. The local runtime credentials, database, machine paths, and raw private working records are not public distribution artifacts.


## Version 0.5.0 specification and interaction extension

Reused the answered brief to generate 16 populated specification documents, including a copyable UI/UX prompt, design rules, page/action/motion contracts, seven module specifications and traceability. Six renderer behavior tests and 13 application tests passed; production HTTP verified 13 routes. Six isolated interaction studies were operated and captured at desktop, phone and actual preview widths. An independent source/screenshot reviewer scored five listed corrections resolved; that scope does not constitute independent temporal acceptance.

Observed corrections included scroll coordinate spaces, final radial clipping and resizing, inherited checkbox sizing, a live preference subscription, true off-panel reveal origins, settled-card guards and in-flight wheel cancellation. The author retained early failed preference checks and browser-tool limits. Physical touch/paused native gestures and later held-pointer instrumentation were not verified. See the repository's [versioned verification](https://github.com/KarmenLoop/fullstack-web-delivery/blob/main/docs/verification.md) for actual evidence rather than transferring older trial counts.

## Version 0.9.0 material implementation

A later narrow request implemented the previously deferred metallic card in the existing atlas: authored environment upload, two blur targets, bevel/grain reflection normals, coupled pointer spring and directional lighting with a layered CSS shadow projection. The actual native Chrome WebGL2 checks read stage/material pixels; pointer input, keyboard light changes and context loss/restoration were operated separately. Device timing, real-phone gestures and comprehensive independent runtime acceptance were not established. See the repository verification for the current source/capture and review scope.
