# Metal card implementation brief

Mode: Experience, supported by Read diagnostics. This is a precise component extension inside the existing motion atlas; inherit its cream/forest typography and semantic controls. The user already specified the material pipeline and requested browser operation. No new visual identity, layout tournament or additional discovery is needed.

## THESIS

A reflective specimen whose rendered surface and physical tilt share one state, with inspectable GPU stages.

The follow-up adds controllable directional light, face and bevel highlights, and soft cast shadow. Light direction/intensity remain ordinary keyboard-operable controls. GPU highlights and the layered CSS shadow projection are identified separately; no ray-traced or full PBR claim.

## OWN-WORLD

Keep the atlas identity and ordinary accessible controls. One authored aluminium surface carries the material study. Its environment is a local procedural studio panorama; no original video pixels, external assets, camera or screen capture.

## STORY

Find Material in atlas navigation; move over the card, change the environment or finish, inspect normals/reflection and the raw/horizontal/vertical pipeline. Run actual GPU readback checks. Lose and restore the context through the provided extension when supported; readable content survives.

## FIRST VIEWPORT

Direct material heading and purpose; a large responsive card beside a compact control column. Three small processing views explain the source and two blur passes. The material leads; diagnostics expand on demand.

## FORM

Code-led narrow extension. Seed and approved comp: NOT_APPLICABLE. Render a rounded-card distance field, bevel normals and stable grain in WebGL2. Upload a 512x256 authored environment, blur horizontally into one FBO then vertically/desaturate into another. Reflect a normalized view ray using the rotated normal. CSS card transform and shader rotation use the same spring angles and 1000px perspective convention.

## FINISH

Retain semantic DOM labels, native controls and stable hit area. Keep reduced-motion/coarse-pointer static paths; stop on settle, offscreen and hidden page. Cap DPR and release owned resources. Inspect desktop/phone together, correct observed defects in one batch, then confirm affected scope. Independent review scores its own bounded source/capture scope.

## Implementation and acceptance plan

1. Add a standalone renderer/math module and a React component; no runtime dependency. Retain SSR, existing API, authentication, consultation data and routes.
2. Integrate the component into /motion-atlas with a Material anchor. Supply surface/normal/reflection views, source/H/V thumbnails, environment/roughness/grain controls and written renderer state.
3. Validate spring retargeting/settling with meaningful numeric tests. In the browser compile/link shaders, inspect FBO completeness, read actual stage pixels and compare material output under tilt, bevel and grain changes.
4. Operate pointer, leave/reentry, controls, resize, reduced motion, keyboard, phone width, context loss/restore, route teardown/remount and production build. Distinguish actual browser GPU execution from physical-device/FPS acceptance.
5. Repair observed failures, record actual source and runtime evidence, keep a reachable production preview and open it for the user. Update the material recipe with the working source and learned constraints.
