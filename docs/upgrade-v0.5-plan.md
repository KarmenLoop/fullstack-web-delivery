## UI and motion contract

The lab extends the established cream/forest system. It is an Operate/Experience workbench for developers and designers: a concise purpose, a six-item pattern index, one live canvas, accessible controls, and an adjacent explanation of the state/feedback contract. It is not a new marketing identity or six equal decorative feature cards. Each study has an observable task and state, not an autoplay loop.

Immediate press feedback starts at input. A pending operation remains distinct from success. Linked elements derive from one state source. Expansion reverses from its current position. A timeline advances after the card settles. Wheel selection commits to a bounded tick with keyboard/select alternatives. Radial transitions originate at the actual trigger and change the route; Back/Forward and reduced motion retain useful navigation.

## Acceptance and limits

All six studies must have real controls, a result, keyboard access, interrupted/repeated use behavior, a reduced-motion alternative and no page overflow at the actual tested viewport. The specification pack must tell an implementer who each page serves, the content and primary action, action target, state, feedback, motion, data dependency and verification. It must not invent proof, install unnecessary modules, overwrite edited documents, or imply publication authority.

Target evidence: local commands/exit codes, generated-file manifest and traceability, real browser state observations and captures, named test/CI results, and scoped independent review. Physical touch devices, complete accessibility/performance certification and additional agent platforms remain separate untested scopes.
