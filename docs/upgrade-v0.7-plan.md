## Placement and operation

| Requirement | Location and purpose | Driver and result |
| --- | --- | --- |
| Scroll-triggered card reveal | Educational mechanism rows; introduce grouped material once | IntersectionObserver; short opacity/translation, visible fallback |
| Scroll-linked progress | Scroll lesson progression | Actual section scroll progress, not a time-driven fake |
| Parallax | Bounded decorative depth within the scroll lesson | Small transform distance; removed with reduced motion |
| Sticky explanation | Context beside a longer lesson | Native CSS sticky; normal flow at short/narrow layouts |
| Horizontal scroll and snap | Mechanism comparison rail | Native overflow and CSS snap, explicit Previous/Next and keyboard access; no wheel hijacking |
| Button-to-orb and node check | Existing real staff login | Pending at input, check only after server confirmation; retain failure and input; bounded transition to admin |
| Odometer | Known selected-role/capability counts | Derive digits from actual loaded demo data; no false zero during loading; stable accessible text |
| Command+K | Atlas permission question and team search | Radix focus-managed dialog, immediate opening, server policy lookup, visible source and selected result |
| Growing relationship graph and route light | Atlas department map | Stable entity IDs and server-held fictional data; root path selection, interruptible trace |
| Heatmap wave | Department activity demonstration | Declared synthetic values, bounded stagger from selection, text equivalent and legend |
| Inline detail and neighbors yielding | Department rows | Disclosure in document flow with layout transforms; focus and identity preserved |
| Card launch into place | Assignment continuity study | One stable card ID moves between source and destination; reversible and bounded |
| Dark appearance | Atlas and its command palette | Semantic tokens, persisted local preference, readable contrast and reduced-motion-safe switch |

Each implemented placement will be recorded in a generated MOTION-MAP.md with page/element, task, trigger, driver, timing, interruption, alternatives and actual acceptance method. Effects are chosen by task on future projects; this atlas is an explicit demonstration, not a rule to animate every customer page.

## Frontend, API, policy and storage

Reuse React SSR, Motion, Radix Dialog, Express and SQLite. Add no animation dependency. Split the reusable authentication-feedback and rolling-number components from the atlas page. Scroll effects use native browser behavior and existing Motion values, with cleanup and resize/reduced-motion handling.

Add a read-only `/api/demo/access-map` endpoint. Its server-owned fictional policy/department/activity fixture supports a bounded query, including the requested permission question in English and Chinese. Return model version, explicit illustrative/read-only scope, matching role IDs and their source rule. This endpoint neither reads real staff identities nor grants/revokes permissions. Existing server-side inquiry authorization remains authoritative and distinct. No external AI provider or permission-mutation integration is configured or claimed.

The existing login still uses `/api/login`, actual credential verification, CSRF and persistent sessions. Visual success waits for that response. Theme preference is local to the atlas; no credentials or command content is synchronized. Graph/demo data is separate from actual SQLite users and inquiries. No destructive migration is needed.
